# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

Web app that generates judging packets for figure skating competitions. Users upload PDF exports from Figure Skating Manager (FSM); the backend splits, categorizes, and merges them into per-judge/referee/official PDF packets. UI is bilingual (Finnish default, English).

**This repo is backend-only.** The frontend was moved to the `figureskatingtools-site` repo, which serves it at `https://figureskatingtools.com/judgepapers/` and proxies `/judgepapers/api/*` here. `PROXY-CONTRACT.md` is the authoritative description of the router → Function App contract.

```bash
# Tests (from infra/functions; in-memory storage fakes, no Azure needed)
uv run --with-requirements requirements.txt --with-requirements requirements-dev.txt \
  python -m pytest tests -q

# Exercise an endpoint the way the site router does (see PROXY-CONTRACT.md "Local testing":
# the secret is required, and tid/oid must be GUIDs)
curl -s http://localhost:7071/api/check_user_permission \
  -H 'x-proxy-secret: local-dev-secret' \
  -H 'x-forwarded-user-tid: 00000000-0000-4000-8000-000000000001' \
  -H 'x-forwarded-user-oid: 00000000-0000-4000-8000-000000000002' \
  -H 'x-forwarded-user-email: you@example.com'

# Deployment (manual; CI does this automatically on push to main / dispatch)
./deploy_infra.sh -g <resource-group> [--proxy-secret <SECRET>] [--orphan-purge true|false]   # Bicep, subscription-scoped
# --orphan-purge omitted = keep the deployed ORPHAN_PURGE_ENABLED (false if unreadable), never the Bicep default true
./deploy_backend.sh -g <resource-group>       # Functions ZIP deploy
```

The pytest suite lives in `infra/functions/tests/` (`conftest.py` + `fakes.py`: in-memory table/blob doubles, every storage entry point faked, the platform clock off unless a test asks for the `platform` fixture, and the autouse `access` fixture faking the platform's access tables — the default caller owns `PLATFORM_ID`; `test_access.py` holds the role matrix of every competition route); CI runs it as the `pytest` job. No linter is configured. To drive the backend from a UI, run the frontend from the `figureskatingtools-site` repo and point its judgepapers function-app URL at `http://localhost:7071`.

## Architecture

Two pieces deployed from here, plus a frontend that lives elsewhere:

1. **Frontend** — *no longer in this repo.* The `figureskatingtools-site` repo hosts a single App Service that serves every tool's UI (`/judgepapers/`, `/scoremodifier/`, …), owns Easy Auth and the `figureskatingtools.com` domain, and proxies `/judgepapers/api/*` to the Function App deployed here.

2. **Backend** (`infra/functions/`) — Python Azure Functions, all HTTP-triggered, defined in `function_app.py`. The PDF pipeline lives in plain modules called by the `generate_judging_papers` endpoint:
   - `processor.py` — orchestrator: parse CompetitionSchedule → extract segment names → split judge sheets → generate cover pages → merge per-person packets → ZIP. Runs on local temp dirs after downloading blobs.
   - `split_judges_sheets.py` — splits `*_JudgesSheetAll.pdf` into per-judge/referee PDFs by parsing role lines; also detects withdrawn skaters (`is_withdrawn_page` recognises both the wide-column `WD    Name` layout and the single-space `WD Name` one used by the Technical Controller/Specialist sheets, scanning only the page's header block so a `WD Name` row deeper in a table doesn't condemn the page, and ignoring the `WD  Withdrawn` legend; `filter_withdrawn_pages` copies a PDF without those pages). Step 3 of `processor.py` runs that filter over the per-skater `*_TechnicalControllerSheet.pdf` / `*_TechnicalSpecialistSheet{1,2}.pdf` before merging them into the packets, caching the result as `*_nowd.pdf` (written once per segment, reused by every official). The referee sheet is deliberately left whole: it is a per-segment table with all skaters as rows, so a page-level filter would drop the entire table.
   - `create_cover_pages.py` — reportlab cover/segment pages, strikethrough start lists. What precedes each segment in a packet is chosen by `processor.segment_intro_page` from the generate `options`: the generated segment cover (`globalSegmentCover` / per-prefix `segmentCovers`), the time schedule (`StartListwithTimes`, struck through for withdrawn skaters; the default) or nothing (`globalOmitSegmentCover` / per-prefix `omitSegmentCovers`, which wins; the site's "No cover page or time schedule before the segments" checkbox). The personal cover page at the front of every packet is always kept.
   - `combine_judging_papers.py` — date/time/panel extraction and final merge.
   - `email_sender.py` — the "send judges' papers" e-mail used by `POST send_judge_papers`: FI/EN templates (the 🎥 video line is dropped while `EXAMPLE_VIDEO_URL` is empty), address/sender-name validation, a MIME message built with the stdlib `email` package (RFC 2047 headers, UTF-8 quoted-printable text + HTML parts; From `Figureskatingtools.com <no-reply@figureskatingtools.com>` (the sender name only signs the body), Cc = the Results Service e-mail, no Reply-To) posted to Mailgun's EU `messages.mime` endpoint with tracking off. Every mail's footer links the site's privacy notice (`PRIVACY_NOTICE_URLS`: `/tietosuoja/` FI, `/privacy/` EN). No `MAILGUN_API_KEY` = dry run (only the subject and the recipient count are logged — the body holds a live download link, and addresses never go to the logs — nothing sent). The endpoint only sends `judgingpapers_*.pdf` files that have a `generatedpapers` row, e-mails no storage URL (Microsoft junked mail linking to `*.blob.core.windows.net`) but `{PUBLIC_BASE_URL}/judgepapers/download?t=<token>`, a random 32-character token stored as the `sentemails` RowKey (the row is written before sending and removed if Mailgun fails), valid 5 days but capped at the competition's *effective* deletion date — the platform's for a bound record, see Retention below (409 when under an hour remains, 410 `platform_deleted` when the platform competition is gone). The site router proxies that public path, excluded from Easy Auth, to the anonymous `GET download_judge_papers`, the one route with no user header (proxy secret still checked): it resolves the token, returns a bilingual plain-text 404 for a malformed token and 410 for an expired link or one whose data is gone (no `sentemails` row — deleted with the competition —, competition hidden, file missing; the competition is fetched with `_get_competition_entity_strict`, so a storage outage is a retryable 503, never a 410), bumps `DownloadCount`/`LastDownloaded` and redirects 302 to a 15-minute read SAS (`generate_blob_read_sas_url`, shared with `_generated_file_links`). `PUBLIC_BASE_URL` comes from the `publicBaseUrl` Bicep param, which `deploy.yml` sets per environment. The endpoint allows 20 sends per user per 24 h (429), checked *after* writing the row (count > 20 → the row is deleted and 429), so concurrent sends can't overshoot the limit; it fails closed (503) when the count can't be read. `POST preview_judge_papers_email` takes the same body (addresses optional), runs the same validation (`_parse_send_request`) and returns `{subject, from, to, cc, html, expiryDisplay}` rendered by `email_sender.render_preview` — no SAS minted, nothing sent or counted — for the site's send-dialog preview. `POST create_download_link` (`{id, fileName}` → `{url, expiration}`, the site's "Copy link") creates the same token link without sending anything, for sharing anywhere: shared `_link_expiry` (same 5-day cap, 409, 410) and `_public_download_url` with the send path; any generated file (`_LINKABLE_FILE_RE`, PDF or ZIP, with a `generatedpapers` row and its blob); **read** access is enough; its `sentemails` row has `Channel` `link`, `SentByOid`, empty `To`/`Cc`; `LINK_RATE_LIMIT_PER_DAY` (100) per user by `SentByOid`, checked after writing like the e-mail limit, which ignores link rows; bumps `LinkCreatedCount`.
   - `categories.py` — table-driven category lookup (see below).
   - `competition_schedule.py` — parses the CompetitionSchedule PDF for start times.
   - `combined_schedule.py` — the optional combined time schedule of a day (`globalCombinedSchedule`, the site's "Combined time schedule of the day at the end of the papers" checkbox, off by default; `processor.combined_schedule_enabled`; `combinedScheduleCopies`, the site's copies field next to it, 1–50, a non-integer = 1, `processor.combined_schedule_copies`): every segment whose `StartListwithTimes` falls on that date, in running order, warm-up rows on pale green and resurfacing rows on pale amber bands, each block followed by its parameter lines (Resurfacing, Warm-Up, Duration of Skating / Introduction, Judging First, Judging Last), WD rows and judges'-sheet withdrawals struck through, the competition banner copied from the StartList, and in the footer the sources' `printed:` range, `n / N` and the `FOOTER_TEXT` brand line of the cover pages. English labels, category/segment names as FSM prints them. `processor.build_combined_schedules` writes `combinedschedule_{date}.pdf` once per day (step 2.6), and step 4 adds that many copies at the end of the day's document `judgingpapers_{date}.pdf` (all packets of the day); the personal packets in the ZIP don't get it. It is an add-on and replaces nothing (it combines with any `segment_intro_page` choice). The StartLists are parsed with **pdfminer.six** from character positions, because pypdf merges a row into one string and, on Free Skating lists, puts the CurrentRank/Points columns before the name. The banner image (every XObject drawn above the first text) is copied unchanged and drawn by a content stream placed *in front of* the reportlab page: pypdf's `merge_page` re-serializes reportlab's subset-font strings and drops characters such as Ä/Ö. The table uses the bundled Liberation Sans (OFL, `assets/fonts/LiberationSans-OFL.txt`): Raleway has old-style figures and no Latin Extended. Best-effort: a day whose lists can't be read gets no page.

3. **Infra** (`infra/main.bicep` + `modules/`) — subscription-scoped Bicep, backend-only: resource group, storage (`storage.bicep`), Function App + App Insights on a 90-day Log Analytics workspace (`function.bicep`, Flex Consumption, **SystemAssigned identity only**, CORS empty), and storage RBAC (`roleassignment.bicep`). Params are just `resourceGroupName`, `location` and the secure `proxySharedSecret`; per-env values in `infra/parameters/{test,prod}.bicepparam`. `main.bicep` exports `functionPrincipalId` so the site repo can grant this Function App read access to the shared competition-data container. **No Web App, managed identity, DNS or custom-domain modules live here any more** — hosting, Easy Auth, the `figureskatingtools.com` zone and all custom domains belong to the `figureskatingtools-site` repo.

### Auth chain (important when touching any endpoint)

Full details in **`PROXY-CONTRACT.md`** (keep it in sync when touching this). Summary:

All function routes are `AuthLevel.ANONYMOUS`; real auth is Entra ID Easy Auth on the site router. Identity flows: Easy Auth injects `X-MS-CLIENT-PRINCIPAL*` headers on the router → the router forwards `x-forwarded-user-tid` / `-oid` (Entra tenant + object id, the identity), `-email` (lowercased, display/audit only), `-name` (URI-encoded) and `-admin: 1` for site admins, plus `X-Proxy-Secret` → `get_caller()` in `function_app.py` checks the shared secret first (fail closed, `hmac.compare_digest`), then builds a `Caller` from those headers **only** — no Easy Auth, base64-principal or Bearer-JWT fallbacks; a missing/non-GUID tid or oid is `None`. Every endpoint must call it and return 401 on `None`. `is_user_allowed(caller)` currently allows all authenticated users and is the hook for a future allowlist.

**Competition access.** Each competition is private to its owner and the users it is shared with on the site. `platform_access.py` — keep it **byte-identical** with fs-protocolgenerator and fs-scoremodifier, like `platform_clock.py` — maps the caller's `<tid>_<oid>` to the platform `UserId` (table `useridentities`, `PLATFORM_IDENTITIES_TABLE`) and reads the `Role` (`owner` > `write` > `read`) from `competitionaccess` (PK platform GUID, RK UserId; `PLATFORM_ACCESS_TABLE`), both on `PLATFORM_STORAGE_ACCOUNT` through table-scoped Reader grants made by the site repo; admins count as owner without lookups; answers are cached 30 s. Every route that takes a competition goes through `_competition_for(caller, id, need)` (record → `PlatformId` → `_access_error`) before touching anything: **read** = `get_competition_details`, `create_download_link`, `resolve_competition` (incl. creating the empty bound record), `list_competitions` (filtered to readable records; admins see all); **write** = settings, generate, preview/send e-mail, upload, import, delete file; **owner** = delete competition (`POST delete_competition` only, id from `?id=` or JSON `{"id"}`). `resolve_competition` renames an existing record to the client-sent name only for write/owner callers (`can_rename`). No access, unknown, hidden, or an unbound record (no `PlatformId`) for a non-admin → 404 `platform_not_found`; read on a write route → 403 `platform_read_only`; read/write on an owner route → 403 `platform_owner_required`; access tables unreadable (incl. unset `PLATFORM_STORAGE_ACCOUNT`) → 503 `platform_unavailable` (fail closed). New competition routes must use `_competition_for` and be added to `ROUTES` in `tests/test_access.py` (a test enumerates the HTTP routes). `CreatedBy` stays an e-mail for history only. PROXY-CONTRACT.md has the full table.

**The Function App itself must be `AllowAnonymous`** (`function.bicep` `globalValidation`), *not* `requireAuthentication: true` — the router forwards only identity headers, no bearer token, so Easy Auth enforcement would 401 every proxied request (`WWW-Authenticate: Bearer`, empty body) before the app's header check runs. No identity provider is registered on the Function App at all.

Because the function endpoint is public, a **shared secret** stops anyone from calling it directly with spoofed identity headers: the router holds the secret and sends it as `X-Proxy-Secret` on every proxied call, and `_proxy_secret_ok()` (called first in `get_caller`, and by `download_judge_papers`) rejects requests whose header doesn't match → 401. It **fails closed**: an empty `PROXY_SHARED_SECRET` rejects everything (only `health` is ungated), so local dev needs it in `local.settings.json` too. The secret is a per-environment GitHub Environment secret here, injected into the Function App via the `proxySharedSecret` Bicep param (in the authoritative `appSettings` array); the same value lives in the site repo as `PROXY_SHARED_SECRET_JUDGEPAPERS`. Two rejected alternatives: inbound **IP restrictions** `403` the GitHub runner during the Flex deploy's sync-triggers/health-check and hang the pipeline; **Network Security Perimeter** can't hold `Microsoft.Web` apps (not an onboarded NSP resource type).

### Storage layout & dual credential pattern

Every competition has an immutable 8-char hex **id** (`uuid4().hex[:8]`) — the identifier in all API calls and table keys. Competition **names are not unique** (trial-and-error re-creation is allowed); the blob folder is `{sanitized-name}-{id}/`, stored on the entity as `FolderPath` (endpoints resolve id → FolderPath via `_competition_for`, which also checks access).

Blob container `fs-judgepapers`:
- `{name}-{id}/metadata.json` — id/name/createdBy/createdDate/language/judgingMethodOverrides; its existence defines the competition "folder"
- `{name}-{id}/{PREFIX}_{Suffix}.pdf` — uploaded FSM exports
- `{name}-{id}/judgePapers/...` — generated output (ZIPs + merged PDFs are recorded in `generatedpapers`; links are minted per response)

Tables: `competitions` is the **authoritative, permanent history** of every competition ever created (PartitionKey `GLOBAL`, RowKey = id; rows are never deleted — there is no blob-scan fallback anymore). Columns: `Name`, `FolderPath`, `Visible` (controls UI listing), `CreatedBy/CreatedDate` (`CreatedBy` blanked on delete), `DeletedDate/DeletedBy` (`user`/`auto-cleanup`, never an address), `DeletionDate` (a cached copy of the platform date, see Retention), `PlatformId` (see below; every record created since the platform clock has one), and usage counters for statistics (`UploadedFileCount`, `GenerateRunCount`, `LastGeneratedDate`, maintained best-effort by `_bump_competition_counters`). Deleting a competition removes its blobs and `generatedpapers` rows but only soft-deletes the `competitions` row (`Visible=false` + delete audit). Legacy name-keyed rows are lazily migrated by `list_competitions` (`migrate_legacy_row`: new id-keyed row with `FolderPath` = old name folder, generatedpapers re-keyed). `generatedpapers` records the generated files (PartitionKey = competition id; `BlobName`, `FileName`, `FileSize`, `Description` — no link: `get_competition_details` mints a fresh 15-minute read SAS per file after the access check, `_generated_file_links`, one user-delegation key per response; older rows' stored 5-day `Url` is never returned, only its blob name is used), `categories` is the category registry, `sentemails` is the send-e-mail audit log, download-link registry and rate-limit source (PartitionKey = competition id, RowKey = the link token; `SentBy`, `To`, `Cc`, `FileName`, `Language`, `SentDate`, `LinkExpiry`, `MailgunId`, `DryRun`, `DownloadCount`, `LastDownloaded`; copied links add `Channel` `link` and `SentByOid`), deleted with the competition's blobs because it holds recipient addresses (a failure there aborts the delete before the soft-delete, so it can be retried); sends are also counted in `EmailSentCount` on the `competitions` row.

**Platform binding.** The site owns the competition registry and its nav selector's "active competition" (a GUID). `POST /resolve_competition` (`{platformId, name}` → `{id, name, created, deletionDate}`) maps that GUID onto this tool's own record so the site's UI needs no per-tool competition list: first checks read access to the platform competition (404 `platform_not_found` / 503 `platform_unavailable`, before the 410 check so nothing leaks), then looks it up by `PlatformId` (server-side filter, `Visible is False` filtered in Python because legacy rows lack the property and soft-deleted rows keep their `PlatformId` while their blobs are gone; newest `CreatedDate` wins; when the sanitized platform name differs from the stored `Name` and the caller has write or owner, `_sync_competition_name` MERGE-writes the new `Name` and best-effort rewrites `name` in `metadata.json`, so a rename on the site follows through — `FolderPath` is deliberately immutable, blob paths and generated-paper URLs hang off it) → else creates one via `create_competition_record` (requires a `platform_id`; `resolve_competition` is the only creator — the standalone `create_competition` route is gone). Unbound records are **never adopted by name** any more (removed with competition access: it let anyone capture another user's record); a legacy unbound record stays admin-only. A *new* binding (creation) needs the platform row to be readable: 404 `platform_not_found` when the registry has no such competition, 503 `platform_unavailable` when it can't be read; only a deployment without `PLATFORM_STORAGE_ACCOUNT` (local dev) binds without a date. `migrate_legacy_row` never writes a `PlatformId` (and only an admin's `list_competitions` runs it). The legacy `list_competitions` (read-only apart from the legacy re-keying) and `delete_competition` routes remain; `create_competition` and `extend_competition_deletion` are removed — extending happens only on the platform (`POST /api/competitions/{id}/extend`, called by the site).

**Retention (one platform clock).** One rule per competition, owned by the platform: the site's registry holds each competition's deletion date (created + 60 d, extended a week at a time on the site only) and mirrors the non-personal part into its own table `retentionclock` (PK `COMPETITION` / RK the lowercase GUID; `DeletionDate`, `Status`, `PurgedUtc`). This tool reads **only** that table (never the registry's `competitions`, which holds addresses and IPs), read-only through a Storage Table Data Reader grant scoped to it (site repo's `shared-data-access.bicep`; `PLATFORM_CLOCK_TABLE` overrides the name). It has **no clock of its own** and no extend route; the row's `DeletionDate` is only a cached copy of the platform date (written by `_sync_local_deletion_date` on resolve, details and the timer) for display and the send cap. `platform_clock.py` reads the platform — keep it **byte-identical** with fs-protocolgenerator and fs-scoremodifier: `normalize_platform_id` (lowercase GUID or None — used before every platform read and every local lookup/store, so a differently-cased GUID never binds a second record; `find_competition_by_platform_id` also finds and rewrites a row stored under another casing), `read_platform_clock` → `{deletionDate, status, purged}`, `None` when the row is missing or `PLATFORM_STORAGE_ACCOUNT` is unset, `PlatformClockUnavailable` on any other failure including a missing table (`TableNotFound`); `platform_says_delete(clock)` is true **only** for `Status == "deleted"` or `PurgedUtc` — a passed date alone never deletes (the platform may be in dry-run, or the competition was just extended). `_platform_clock_reader` builds ONE platform table client (per request, per sweep) and returns `(clock, state)` with state `ok` / `not_found` / `unavailable` / `off` / `unbound`. `resolve_competition` returns 400 for a platformId that isn't a GUID and 410 `platform_deleted` (creating nothing) for a deleted/purged platform competition; `resolve_competition` and `get_competition_details` return the platform's `deletionDate` (cached copy as fallback); the send flow caps the link at it. The 04:00 UTC timer (`run_auto_deletion`, an hour after the platform's 03:00 sweep so it follows the platform's verdicts the same night): bound row with the clock readable → deleted when `platform_says_delete`, otherwise only the cached date is synced; clock unreadable (incl. missing table) or `PLATFORM_STORAGE_ACCOUNT` unset → **skipped** with an error log. Legacy rows without `PlatformId` (from before the platform) are deleted on their stored `DeletionDate` (`LEGACY_DELETION_DATE`, long past, when they have none) and nothing new is written for them. **Orphans** (the platform can no longer decide about them): a live row with no `PlatformId` (legacy name-keyed rows included) or a non-GUID one, or whose clock row a *successful* read did not find, is deleted with the same `_delete_competition_data` flow once it is **more than 60 days old** (`CreatedDate`; without one, the newest of `LastGeneratedDate`/`LastStatisticsDate`/the Table `Timestamp` — `platform_clock.record_age_reference`); younger orphans are kept with a warning, and a read error is never "not found" (skipped). Safety rails: one probe of the clock table per run (`platform_clock.orphan_sweep_allowed`) — unreadable, unconfigured, or **zero rows while the tool has bound rows** (wrong table/account) → the orphan step is aborted for that run with an error log; `ORPHAN_PURGE_ENABLED` (Bicep param `orphanPurgeEnabled`, default on, GitHub var `ORPHAN_PURGE_ENABLED=false` = kill switch) off → it only logs "would delete"; the timer logs the per-run counts (`orphaned`, `orphan_kept`, `orphan_dry_run`, `orphan_skipped`). **No addresses outlive the data:** `_delete_competition_data` blanks `CreatedBy` and stores `DeletedBy` = `user` | `auto-cleanup` (metadata.json with `createdBy`, the `sentemails` rows and `importedBy` blob metadata go with the data), and every nightly run also calls `_scrub_hidden_rows`, which blanks any `CreatedBy`/`DeletedBy` still holding something other than `""`, `-`, `user`, `auto-cleanup` on hidden rows deleted before this. Logs carry no addresses or personal names either (auth logs say only which header identified the caller; the send log counts recipients). Logs are kept **90 days**: `function.bicep` links the App Insights component to its own Log Analytics workspace `log-fs-judgepapers-<env>` (`retentionInDays: 90`) and sets `RetentionInDays: 90` on the component (`logRetentionDays`).

**Pool refresh.** Blobs copied in from the pool carry `poolSource` / `poolUploadedUtc` / `importedBy` blob metadata (`_copy_pool_blob`, shared by `import_platform_file` and the refresh). Both read paths — `get_competition_details` and `generate_judging_papers` — first run `_refresh_from_pool`, which re-copies any file the tool *already holds* whose pool copy (`uploads/` or `fsm/`, newest of the two) is newer than the stamped `poolUploadedUtc`, so an FSM re-export under the same stable filename replaces the tool's copy automatically instead of generating from a stale one. It never adds or deletes files — new pool files still need an explicit import — and it is best-effort: every failure is logged and swallowed. `get_competition_details` reports what it replaced as `refreshedFromPool` and returns per-file `uploadedUtc` (the pool upload / FSM push time — what the UI shows), `lastModified` (when this copy was written) and `poolSource`.

Every storage client helper supports two credential modes and new storage code must too: managed identity when `AzureWebJobsStorage__accountName` is set (production; SAS via user-delegation key), connection string via `AzureWebJobsStorage` otherwise (local dev; SAS via account key).

### Category/filename parsing

FSM filenames are `{CATEGORY_ABBREVIATION}{SEGMENT_MARKER}_{Suffix}.pdf` (e.g. segment markers `QUAL`/`FNL`, split suffixes `#N`). Abbreviations are not hardcoded — they live in the `categories` Azure Table (RowKey = abbreviation, with `DisplayName`, `DisplayNameFi`, `JudgingMethod` = ISU|MUPI) and are matched longest-prefix-first. `categories.py` caches the table in memory for 5 minutes. The table's `JudgingMethod` is only the *default*: synchronized-skating categories (`is_synchronized_skating`, a casefold compare of the PartitionKey, since live rows use both `Synchronized skating` and `Synchronized Skating`) can be overridden per competition via `metadata.json`'s `judgingMethodOverrides` (`{abbreviation: ISU|MUPI}`, validated on write by `save_competition_settings`, sanitized on read). `get_competition_details` applies them — each file gets the effective `judgingMethod` plus `defaultJudgingMethod` and `judgingMethodOverridable` — and `_compute_statistics` applies them via `options['judgingMethodOverrides']`, which `generate_judging_papers` reads from metadata.json (a client-sent value is ignored); the PDF pipeline itself never reads the judging method. This parsing logic is duplicated in spirit on the frontend (`validate.ts` consumes the parsed structure from `get_competition_details`).

Human-readable segment names aren't in filenames; they're extracted from line 2 of each `JudgesSheetAll.pdf` (stripping the category display name prefix, with punctuation-tolerant fuzzy matching). This enrichment happens both in `function_app.py` (`get_competition_details`) and `processor.py`.

## Branch / Deploy Strategy

**Flow (no long-lived `test` branch):** branch from `main` → dispatch `deploy.yml` on that branch with `environment=test` → PR to `main` → merge with **squash** (one commit per release on `main`) → push to `main` deploys prod → the branch is auto-deleted on merge. `main` is guarded by the "Protect main" ruleset: PR required, code-owner review (`.github/CODEOWNERS`: `* @mmaraa`), squash only, the `build` and `pytest` checks (`.github/workflows/ci.yml`, every PR — `build` installs `requirements.txt`, imports the dependencies and byte-compiles the backend; `pytest` runs `infra/functions/tests`) must pass, no force-push/deletion; repository admins can bypass, which is how the owner merges their own PRs. The `prod` GitHub environment only accepts deployments from `main`; `test` accepts any branch and holds whichever was deployed last. Dependabot opens its PRs against `main` like any feature branch. `.github/workflows/deploy.yml` has two deploy jobs — infra (Bicep) then backend (Functions ZIP) — targeting the matching GitHub environment: **push to `main` auto-deploys prod**; **`test` is manual-only** via `workflow_dispatch` (run the workflow from the branch whose code you want, pick the environment) — there is no `test`-branch push trigger. This mirrors the figureskatingtools-site repo. There is **no frontend job and no Entra/Graph step** any more; the environments need only `AZURE_CLIENT_ID` + `PROXY_SHARED_SECRET` + `MAILGUN_API_KEY` (Mailgun domain sending key for `figureskatingtools.com`, EU region; empty = e-mail dry run) secrets, the optional `EXAMPLE_VIDEO_URL` var, the optional `ORPHAN_PURGE_ENABLED` var (`false` = the nightly orphan step only logs; unset = on), the `PLATFORM_STORAGE_ACCOUNT` var (the site's `stfsplat*` account: pool import and the retention clock — required in every deployed environment; empty = pool import off and auto-deletion of bound competitions skipped), and the `AZURE_TENANT_ID` / `AZURE_SUBSCRIPTION_ID` / `LOCATION` / `RESOURCE_GROUP_NAME` vars (`AUTH_CLIENT_ID`, `AUTH_APP_OBJECT_ID` and `CUSTOM_DOMAIN` are obsolete and can be deleted). All jobs in `deploy.yml` pin `runs-on: ubuntu-26.04` rather than `ubuntu-latest` ([actions/runner-images#14748](https://github.com/actions/runner-images/issues/14748) flips `-latest` from 24.04 to 26.04 between 2026-10-19 and 2026-11-19); bump that label deliberately — verify via a `test`-environment dispatch first, roll back to `ubuntu-24.04` if needed — and never set it back to `ubuntu-latest`.
