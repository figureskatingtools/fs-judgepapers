# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

Web app that generates judging packets for figure skating competitions. Users upload PDF exports from Figure Skating Manager (FSM); the backend splits, categorizes, and merges them into per-judge/referee/official PDF packets. The UI is English only; only the e-mail to the judges has Finnish and English templates.

**This repo is backend-only.** The frontend was moved to the `figureskatingtools-site` repo, which serves it at `https://figureskatingtools.com/judgepapers/` and proxies `/judgepapers/api/*` here. `PROXY-CONTRACT.md` is the authoritative description of the router → Function App contract.

The pytest suite lives in `infra/functions/tests/` (`conftest.py` + `fakes.py`: in-memory table/blob doubles, every storage entry point faked, the platform clock off unless a test asks for the `platform` fixture, and the autouse `access` fixture faking the platform's access tables — the default caller owns `PLATFORM_ID`; `test_access.py` holds the role matrix of every competition route; `test_competition_schedule.py` draws FSM-like CompetitionSchedules (`make_schedule`, either time notation) and `test_schedule_check.py` covers the schedule check and the details' `scheduleCheck`; `test_trainee_packets.py` drives the trainee pipeline over empty placeholder files, `test_trainee_pipeline.py` runs it end to end over synthetic FSM-like PDFs, including the split of a real multi-judge JudgesSheetAll; the fake blobs carry an ETag that changes on every write and honour `etag` + `match_condition` like the SDK, and `before_upload` stands in for a concurrent writer); CI runs it as the `pytest` job. No linter is configured. To drive the backend from a UI, run the frontend from the `figureskatingtools-site` repo and point its judgepapers function-app URL at `http://localhost:7071`.

## Architecture

Two pieces deployed from here, plus a frontend that lives elsewhere:

1. **Frontend** — *no longer in this repo.* The `figureskatingtools-site` repo hosts a single App Service that serves every tool's UI (`/judgepapers/`, `/scoremodifier/`, …), owns Easy Auth and the `figureskatingtools.com` domain, and proxies `/judgepapers/api/*` to the Function App deployed here.

2. **Backend** (`infra/functions/`) — Python Azure Functions, all HTTP-triggered, defined in `function_app.py`. The PDF pipeline lives in plain modules called by the `generate_judging_papers` endpoint:
   - `processor.py` — orchestrator: parse CompetitionSchedule → extract segment names → split judge sheets → generate cover pages → merge per-person packets → ZIP. Runs on local temp dirs after downloading blobs.
   - `split_judges_sheets.py` — splits `*_JudgesSheetAll.pdf` into per-judge/referee PDFs by parsing role lines; also detects withdrawn skaters (`is_withdrawn_page` recognises both the wide-column `WD    Name` layout and the single-space `WD Name` one used by the Technical Controller/Specialist sheets, scanning only the page's header block so a `WD Name` row deeper in a table doesn't condemn the page, and ignoring the `WD  Withdrawn` legend; `filter_withdrawn_pages` copies a PDF without those pages). Step 3 of `processor.py` runs that filter over the per-skater `*_TechnicalControllerSheet.pdf` / `*_TechnicalSpecialistSheet{1,2}.pdf` before merging them into the packets, caching the result as `*_nowd.pdf` (written once per segment, reused by every official). The referee sheet is deliberately left whole: it is a per-segment table with all skaters as rows, so a page-level filter would drop the entire table.
   - `create_cover_pages.py` — reportlab cover/segment pages, strikethrough start lists. The **personal cover** (landscape A4 folded down the middle; the right half is the front) shows the competition, date and name, then the person's segments of the day in running order: start time, `Category, Segment` exactly as line 2 of the JudgesSheetAll prints them (`prefix_category_names` / `prefix_segment_names` via `processor.cover_segment_label`, never the categories table) and the role as the panel PDF prints it (`get_panel_info` returns `(role, name, label)`, `Judge No.3` → `Judge 3`). Covers are made in step 2.7, after the 2.5 conflict filter, once every panel has been read. The table uses Liberation Sans (`TABLE_FONT`, registered here and imported by `combined_schedule.py` along with `_fit`). Names that Raleway can't draw fall back to it (`_font_for`). The table sits just above the footer and grows upward toward the name; rows shrink to fit, and past about 16 segments the last row reads `+ N more`. Only the **first cover of the day document** `judgingpapers_{date}.pdf` (step 4) gets the Results Service's grey check block in the bottom-left corner, the back cover once folded (`processor.day_summary` → `_draw_day_summary`). It shows packets (= people) with the number of people per role group, distinct categories (printed name without `#N`) and segments, the day's first start to the last StartList row's end (`get_last_end_time_from_start_list`), and the day document's page count (Σ packet pages + combined-schedule pages × copies; a mismatch with the merged count is logged). Step 4 merges that packet from its parts with the check cover `coverpage_{date}_{slug}_day.pdf` in front. It is best-effort: on any failure the plain packet goes in. The ZIP's personal packets never get the block. What precedes each segment in a packet is chosen by `processor.segment_intro_page` from the generate `options`: the generated segment cover (`globalSegmentCover` / per-prefix `segmentCovers`), the time schedule (`StartListwithTimes`, struck through for withdrawn skaters; the default) or nothing (`globalOmitSegmentCover` / per-prefix `omitSegmentCovers`, which wins; the site's "No cover page or time schedule before the segments" checkbox). The personal cover page at the front of every packet is always kept.
   - The referee's `{category}_CalculationSetupVerificationforReferee.pdf` (one per category or split group, `processor.calculation_setup_prefix`) covers every segment of the category, so step 3 puts it in a referee's packet only in **their first segment of that category** (earliest by date, then start time; step 3 walks the days in date order, so it spans days): the same referee in QUAL and FNL gets it once, a different referee on another segment gets their own copy, and a referee of several categories gets each category's. `globalCalculationSetupEverySegment` (`processor.calculation_setup_every_segment`, only a JSON `true`; the site's "Referee's calculation setup in every segment" checkbox under "Papers to print", off by default) restores the old copy-per-segment behaviour. The referee sheet and the referee's judges' sheet stay in every segment.
   - **Pattern Dance segments** (`processor.is_pattern_dance`: the segment name from JudgesSheetAll line 2 contains `PATTERN DANCE` or `PD` + optional letter + digit, e.g. `PDK1 (Starlight Waltz)`) leave out the papers of `PATTERN_DANCE_SKIPPED_ROLES` — the Data / Replay Operators' `PlannedProgramContent` and the `TechnicalSpecialistSheet1` — by default (issue #72); the page before the segment (time schedule / cover) is added as usual, and the referee, judges, Technical Controller and TS2 keep their papers. `globalPatternDanceAllPapers` (`processor.pattern_dance_all_papers`, only a JSON `true`; the site's second "Papers to print" checkbox) keeps them.
   - **Trainees** (issue #93): people named in this tool, not on the FSM panel, who get a packet of copies of an official's sheets with their own name on them. Stored in `metadata.json` as `trainees: [{name, role: judge|technical, segments: [FSM file prefix, …]}]`; `trainees.py` holds the data model: `parse_trainees` (strict, for the write: at most 50 entries with exactly those keys, the name NFC-normalized, through `email_sender.validate_sender_name`, with at least one letter or digit and drawable in Liberation Sans in both weights, at most 200 segments of 1–100 characters without leading/trailing whitespace, `/`, `\` or control characters; two entries whose names give the same slug must be the same person (`person_key`) — e.g. one person in two roles — else 400 `trainee N: name is too close to trainee M's (they would share one packet); use the same spelling for the same person`; messages name the rule and positions, never a name), `sanitize_trainees` (lenient read side, never raises; drops a later entry whose slug collides with a different person), `TRAINEE_TASKS` (`judge` → task `judge_trainee`, cover label `Judge Trainee`; `technical` → `technical_trainee`, `Technical Trainee`) `person_key` / `same_person` (the one definition of "the same person", for trainee vs trainee and trainee vs panel member: NFKD with combining marks dropped, casefolded, whitespace collapsed, so only case, spacing and diacritics may differ — `Vaino Akerstrom` is `Väinö ÅKERSTRÖM`, `Annamaria Xu` is not `Anna-Maria XU` although both slugify to `annamaria_xu`), `trainee_slug` (`slugify(name)`; when nothing a-z/0-9 is left, `trainee-` + the first 8 hex digits of sha1 of the `person_key`: the same for the same person, and never a slugify result or a panel member's slug, since slugify keeps no `-`) and `separate_slug` (`<slug>-trainee`, likewise never a slugify result nor another trainee's slug). Slugs feed only local file names and names inside the ZIP, and every generated-file regex allows `-`. `process_judging_papers` sanitizes `options['trainees']` itself (missing = no trainees, the pipeline exactly as before). Step 2 remembers per segment with a panel and a start list its date, title and judges' slugs in panel order, then `add_trainee_tasks` adds `(prefix, judge_trainee|technical_trainee)` to `person_tasks[date][slug]` for every stored segment among them (any other stored prefix is ignored, which is how trainees survive a re-import); one packet per person, decided by `person_key`, never by an equal slug: a trainee's entries (both roles) are one trainee under the first entry's name and slug; on a day where a panel member is the same person the trainee joins that member's packet (the panel's spelling of the name stays); otherwise the trainee has a packet of their own under their typed name (cover and stamp), named `trainee_slug`, or `separate_slug` of it when a *different* panel member holds that slug on any day the trainee has a packet of their own (decided once per run, so the packets are named alike on every day). Different people therefore never share a packet. Step 2.5 (which, given the above, only ever meets one person) drops `judge_trainee` where the same person is judge or referee of the segment and `technical_trainee` where they are TS 1 or TS 2 (`TRAINEE_COVERED_BY`), and keeps a person's roles within a segment in the order they were added. Step 3, after the segment's intro page as for everyone: a judge trainee's base is the split `{prefix}_JudgesSheetAll_judge_{slug}.pdf` of the first judge in panel order whose file exists (no named judge: nothing is added, a warning is printed and the segment counts in `trainee_segments_without_sheets`), a technical trainee's is `TechnicalSpecialistSheet2` in a Pattern Dance segment, otherwise `TechnicalSpecialistSheet1`, whatever `globalPatternDanceAllPapers` says (the other one when the chosen file is missing), through `sheet_without_withdrawn` (neither file, or the chosen one failing the withdrawn-page filter as unreadable: nothing, counted the same way, only `type(e).__name__` logged, the run goes on; an official's own TS sheet failing the filter still fails the run as before). The base is stamped once per trainee, segment and sheet per run (tracked in memory, never by a file already lying at the destination, which is overwritten) to `{prefix}_JudgesSheetAll_trainee_{slug}.pdf` / `{prefix}_{sheet}_trainee_{slug}.pdf` (clear of the `*_JudgesSheetAll.pdf` and `*_StartListwithTimes.pdf` walkers), always from the unstamped source. `trainee_sheets.stamp_trainee_sheet(src, dst, kind, name)` finds the role line in the top eight text rows from pdfminer character positions (`Judge No. N` + the name cell, `Technical Specialist[ N]:   <name>`), covers it with white boxes, redraws the covered stretch of a horizontal rule under it and prints `Judge Trainee` + the name (two cells) or `Technical Trainee:   <name>` (one string) in Liberation Sans at the original size, baseline and weight. **No `merge_page`**: the overlay is a Form XObject holding reportlab's bytes unparsed, drawn by a few bytes wrapped around the page's untouched content streams (`q…` / `Q… q /FstTraineeN Do Q`, the q/Q count from the page's own nesting) with a private `/Resources` copy per page — as `combined_schedule._add_banner` does. Pages without a role line pass through. It raises and writes nothing on anything unsafe (a role line it can't place, e.g. on a rotated or offset page; a dashed rule or anything but a plain horizontal rule under the line; no page stamped; an unreadable source; a page-count mismatch on re-read); the processor then puts the unstamped base in, adds its pages to `trainee_sheets_unstamped` and logs only `type(e).__name__` (a base that can't even be read goes nowhere and counts in `trainee_segments_without_sheets`). `generate_judging_papers` (`_generate_warning`) ends its 200 text with ONE ` Warning: ` suffix holding the applicable sentences, `N page(s) of trainee sheets still show the original name.` and `M trainee segment(s) got no sheets to copy.`; the site shows everything after that marker. The official's name stays in the copy's text layer (covered on the page, found by a text search). In the day document, `DAY_ROLE_GROUPS` maps both trainee tasks to the group `trainee` (`ROLE_GROUP_NAMES`: `… · 2 trainees`); a person both on a panel and a trainee counts in both groups. `_compute_statistics` adds `trainee_count` (people), `trainee_assignment_count` (tasks; both stored as `TraineeCount` / `TraineeAssignmentCount`), `trainee_sheets_unstamped` (pages) and `trainee_segments_without_sheets`; a trainee-only person is not in `unique_official_count`, and `unique_judge_count`, `judge_assignment_count` and `officials_by_role` stay about the panel. Log lines never carry a trainee's name or slug.
   - `combine_judging_papers.py` — date/time/panel extraction and final merge.
   - `email_sender.py` — the "send judges' papers" e-mail used by `POST send_judge_papers`: FI/EN templates (the 🎥 video line is dropped while `EXAMPLE_VIDEO_URL` is empty), address/sender-name validation, a MIME message built with the stdlib `email` package (RFC 2047 headers, UTF-8 quoted-printable text + HTML parts; From `Figureskatingtools.com <no-reply@figureskatingtools.com>` (the sender name only signs the body), Cc = the Results Service e-mail, no Reply-To) posted to Mailgun's EU `messages.mime` endpoint with tracking off. Every mail's footer links the site's privacy notice (`PRIVACY_NOTICE_URLS`: `/tietosuoja/` FI, `/privacy/` EN). No `MAILGUN_API_KEY` = dry run (only the subject and the recipient count are logged — the body holds a live download link, and addresses never go to the logs — nothing sent). The endpoint only sends `judgingpapers_*.pdf` files that have a `generatedpapers` row, e-mails no storage URL (Microsoft junked mail linking to `*.blob.core.windows.net`) but `{PUBLIC_BASE_URL}/judgepapers/download?t=<token>`, a random 32-character token whose **sha256 hex** is the `sentemails` RowKey (`KeyKind` `sha256`; the token is stored nowhere; the row is written before sending and removed if Mailgun fails), valid 5 days but capped at the competition's *effective* deletion date — the platform's for a bound record, see Retention below (409 when under an hour remains, 410 `platform_deleted` when the platform competition is gone). The site router proxies that public path, excluded from Easy Auth, to the anonymous `GET download_judge_papers`, the one route with no user header (proxy secret still checked): it resolves the token by its hash (`_download_link_row`; a fallback finds older clear-token rows but only ones **without** the `KeyKind` marker — remove after 2026-12-15), returns a bilingual plain-text 404 for a malformed token (a 64-hex hash never passes `DOWNLOAD_TOKEN_RE`) and 410 for an expired link, a revoked one, one whose creator can no longer read the competition (`_link_creator_denied`: every new row stores `SentByTid`/`SentByOid`, re-checked with `platform_access.role_for(..., is_admin=False)` for a bound record; access tables unreadable → retryable 503; rows without the creator ids skip it. **Known limitation:** `SentByAdmin` is set only when an admin made the link through the admin override alone (`_admin_override_only`: no grant of their own per `role_for(is_admin=False)`; unreadable tables → 503 at creation), and such rows skip the re-check, because admin status lives only in the sign-in token; they are listed and the owner and writers can revoke them. An admin with their own grant gets an ordinary row), or one whose data is gone (no `sentemails` row — deleted with the competition —, competition hidden, file missing; the competition is fetched with `_get_competition_entity_strict`, so a storage outage is a retryable 503, never a 410), bumps `DownloadCount`/`LastDownloaded` and redirects 302 to a 15-minute read SAS (`generate_blob_read_sas_url`, shared with `_generated_file_links`). `PUBLIC_BASE_URL` comes from the `publicBaseUrl` Bicep param, which `deploy.yml` sets per environment. The endpoint allows 20 sends per user per 24 h (429), checked *after* writing the row (count > 20 → the row is deleted and 429), so concurrent sends can't overshoot the limit; it fails closed (503) when the count can't be read. `POST preview_judge_papers_email` takes the same body (addresses optional), runs the same validation (`_parse_send_request`) and returns `{subject, from, to, cc, html, expiryDisplay}` rendered by `email_sender.render_preview` — no SAS minted, nothing sent or counted — for the site's send-dialog preview. `POST create_download_link` (`{id, fileName}` → `{url, expiration}`, the site's "Copy link") creates the same token link without sending anything, for sharing anywhere: shared `_link_expiry` (same 5-day cap, 409, 410) and `_public_download_url` with the send path; any generated file (`_LINKABLE_FILE_RE`, PDF or ZIP, with a `generatedpapers` row and its blob); **read** access is enough; its `sentemails` row has `Channel` `link` (e-mail rows: `email`), the creator columns (`_link_creator_columns`: `SentBy`, `SentByName`, `SentByTid`, `SentByOid`, `SentByAdmin`), empty `To`/`Cc`; `LINK_RATE_LIMIT_PER_DAY` (100) per user by `SentByOid` over link rows only, checked after writing like the e-mail limit, which ignores link rows; bumps `LinkCreatedCount`. `get_competition_details` lists the live links as `shareLinks` (`_share_links`: `linkId` = the RowKey hash, or sha256 of an older clear-token RowKey — never a token; `fileName`, `channel`, `created`, `expiration`, `downloadCount`, `lastDownloaded`, `createdByMe`, `createdBy`; `to`/`cc` only for write/owner/admin, and a read caller sees only their own links; `null` when unreadable), and `POST revoke_download_link` (`{id, linkId}` → `{status: "revoked", linkId}`) revokes one by **marking** its row (`RevokedUtc`, `RevokedByTid`, `RevokedByOid`; never deleting it, so it still counts toward both daily limits): write/owner/admin any link, a read caller only their own (403 `platform_read_only`), 404 `link_not_found` when unknown or already revoked; a revoked link answers the "invalid or removed" 410 without a download count and is left out of `shareLinks`; its row goes with the competition like the rest.
   - `categories.py` — table-driven category lookup (see below).
   - `competition_schedule.py` — parses the CompetitionSchedule PDF (`parse_competition_schedule` → one entry per row: `date` `YYYYMMDD`, `start_time`/`end_time` `HH:MM`, `entries`, and `event_name` / `category_name` / `segment_name` **as printed**). Clock times come in the exporting PC's notation, `14:00:00` or the Finnish `16.00.00`; a row is matched from the start of its line and the trailing duration columns (Resurfacing, Performance, Judging First/Last) are cut off. Category and segment are the two columns of pypdf's layout extraction (2+ spaces apart); a row that came out as one string is split before a known segment name (`combined_schedule.split_title`), then after the longest categories-table name it starts with (`_split_event_name`: `displayName` or `displayNameFi`, compared with `categories._name_end` like line 2 of the judges' sheets; the table only locates the split, the printed text is what is returned, a `#N` included), else `category_name` is `""`. The `printed:` stamp is not a day, rows above the first date line are dropped, an unreadable PDF gives `[]`. The processor uses the entries for the `competitor_count` statistic and as a start-time fallback (the StartList's own time wins).
   - `schedule_check.py` — the schedule check of issue #84, pure functions: `check_schedule(rows, segments, category_keys)` marks every schedule row `found` (an uploaded segment prints the same category + segment: the title of its `StartListwithTimes`, `start_list_title`, or line 2 of its `JudgesSheetAll`, compared with `categories._folded`, so only case, spacing and punctuation may differ; never the categories table), `notNeeded` (no match and 0 entries) or `missing`. One segment covers one row; among rows with the same title a segment goes to the row of its own date first. `categoryKey` is the row's card in the details `structure`: the matched segment's, else the card of a found row of the same printed category, else a structure key of the same name (with or without `#N`), else `null`. `get_competition_details` returns it as `scheduleCheck` = `{rows: [{date: YYYY-MM-DD, startTime, entries, name, category, segment, status, prefix, categoryKey}]}` from what it has already read (no extra downloads), or `null` without a schedule, with an unreadable or empty one, or when the check raises (only `type(e).__name__` logged; never an error response). What a `missing` row means is the site's decision (`validate.ts` `missingReport`): papers are expected only where some are uploaded, since later segments are made once the earlier ones are skated and often only day 1 exists before the competition. So a `missing` row is a quiet "not uploaded yet" note in the category list, except the forgotten category of #84: when no segment of a category has papers (nothing uploaded, or only its calculation setup), its first scheduled segment is marked missing if it is skated on a day that has a `found` row, and Generate asks before going on. **The generate route does not check anything** (the override is a UI safeguard, and the required-file rules live only in the site's `validate.ts`).
   - `combined_schedule.py` — the optional combined time schedule of a day (`globalCombinedSchedule`, the site's "Combined time schedule of the day at the end of the papers" checkbox, off by default; `processor.combined_schedule_enabled`; `combinedScheduleCopies`, the site's copies field next to it, 1–50, a non-integer = 1, `processor.combined_schedule_copies`): every segment whose `StartListwithTimes` falls on that date, in running order, warm-up rows on pale green and resurfacing rows on pale amber bands, each block followed by its parameter lines (Resurfacing, Warm-Up, Duration of Skating / Introduction, Judging First, Judging Last), WD rows and judges'-sheet withdrawals struck through, the competition banner copied from the StartList, and in the footer the sources' `printed:` range, `n / N` and the `FOOTER_TEXT` brand line of the cover pages. English labels, category/segment names as FSM prints them. `processor.build_combined_schedules` writes `combinedschedule_{date}.pdf` once per day (step 2.6), and step 4 adds that many copies at the end of the day's document `judgingpapers_{date}.pdf` (all packets of the day); the personal packets in the ZIP don't get it. It is an add-on and replaces nothing (it combines with any `segment_intro_page` choice). The StartLists are parsed with **pdfminer.six** from character positions, because pypdf merges a row into one string and, on Free Skating lists, puts the CurrentRank/Points columns before the name. The banner image (every XObject drawn above the first text) is copied unchanged and drawn by a content stream placed *in front of* the reportlab page: pypdf's `merge_page` re-serializes reportlab's subset-font strings and drops characters such as Ä/Ö. The table uses the bundled Liberation Sans (OFL, `assets/fonts/LiberationSans-OFL.txt`): Raleway has old-style figures and no Latin Extended. Best-effort: a day whose lists can't be read gets no page.

3. **Infra** (`infra/main.bicep` + `modules/`) — subscription-scoped Bicep, backend-only: resource group, storage (`storage.bicep`), Function App + App Insights on a 90-day Log Analytics workspace (`function.bicep`, Flex Consumption, **SystemAssigned identity only**, `httpsOnly`, CORS empty), and storage RBAC (`roleassignment.bicep`). Params are just `resourceGroupName`, `location` and the secure `proxySharedSecret`; per-env values in `infra/parameters/{test,prod}.bicepparam`. `main.bicep` exports `functionPrincipalId` so the site repo can grant this Function App read access to the shared competition-data container. **No Web App, managed identity, DNS or custom-domain modules live here any more** — hosting, Easy Auth, the `figureskatingtools.com` zone and all custom domains belong to the `figureskatingtools-site` repo.

### Auth chain (important when touching any endpoint)

Full details in **`PROXY-CONTRACT.md`** (keep it in sync when touching this). Summary:

All function routes are `AuthLevel.ANONYMOUS`; real auth is Entra ID Easy Auth on the site router. Identity flows: Easy Auth injects `X-MS-CLIENT-PRINCIPAL*` headers on the router → the router forwards `x-forwarded-user-tid` / `-oid` (Entra tenant + object id, the identity), `-email` (lowercased, display/audit only), `-name` (URI-encoded) and `-admin: 1` for site admins, plus `X-Proxy-Secret` → `get_caller()` in `function_app.py` checks the shared secret first (fail closed, `hmac.compare_digest`), then builds a `Caller` from those headers **only** — no Easy Auth, base64-principal or Bearer-JWT fallbacks; a missing/non-GUID tid or oid is `None`. Every endpoint must call it and return 401 on `None`. `is_user_allowed(caller)` currently allows all authenticated users and is the hook for a future allowlist.

**Competition access.** Each competition is private to its owner and the users it is shared with on the site. `platform_access.py` — keep it **byte-identical** with fs-protocolgenerator and fs-scoremodifier, like `platform_clock.py` — maps the caller's `<tid>_<oid>` to the platform `UserId` (table `useridentities`, `PLATFORM_IDENTITIES_TABLE`) and reads the `Role` (`owner` > `write` > `read`) from `competitionaccess` (PK platform GUID, RK UserId; `PLATFORM_ACCESS_TABLE`), both on `PLATFORM_STORAGE_ACCOUNT` through table-scoped Reader grants made by the site repo; admins count as owner without lookups; answers are cached 30 s. Every route that takes a competition goes through `_competition_for(caller, id, need)` (record → `PlatformId` → `_access_error`) before touching anything: **read** = `get_competition_details`, `create_download_link`, `revoke_download_link` (own links; others' need write), `resolve_competition` (incl. creating the empty bound record), `list_competitions` (filtered to readable records; admins see all); **write** = settings, generate, preview/send e-mail, upload, import, delete file; **owner** = delete competition (`POST delete_competition` only, id from `?id=` or JSON `{"id"}`). `resolve_competition` renames an existing record to the client-sent name only for write/owner callers (`can_rename`). No access, unknown, hidden, or an unbound record (no `PlatformId`) for a non-admin → 404 `platform_not_found`; read on a write route → 403 `platform_read_only`; read/write on an owner route → 403 `platform_owner_required`; access tables unreadable (incl. unset `PLATFORM_STORAGE_ACCOUNT`) → 503 `platform_unavailable` (fail closed). New competition routes must use `_competition_for` and be added to `ROUTES` in `tests/test_access.py` (a test enumerates the HTTP routes). `CreatedBy` stays an e-mail for history only. PROXY-CONTRACT.md has the full table.

**The Function App itself must be `AllowAnonymous`** (`function.bicep` `globalValidation`), *not* `requireAuthentication: true` — the router forwards only identity headers, no bearer token, so Easy Auth enforcement would 401 every proxied request (`WWW-Authenticate: Bearer`, empty body) before the app's header check runs. No identity provider is registered on the Function App at all.

Because the function endpoint is public, a **shared secret** stops anyone from calling it directly with spoofed identity headers: the router holds the secret and sends it as `X-Proxy-Secret` on every proxied call, and `_proxy_secret_ok()` (called first in `get_caller`, and by `download_judge_papers`) rejects requests whose header doesn't match → 401. It **fails closed**: an empty `PROXY_SHARED_SECRET` rejects everything (only `health` is ungated), so local dev needs it in `local.settings.json` too. The secret is a per-environment GitHub Environment secret here, injected into the Function App via the `proxySharedSecret` Bicep param (in the authoritative `appSettings` array); the same value lives in the site repo as `PROXY_SHARED_SECRET_JUDGEPAPERS`. Two rejected alternatives: inbound **IP restrictions** `403` the GitHub runner during the Flex deploy's sync-triggers/health-check and hang the pipeline; **Network Security Perimeter** can't hold `Microsoft.Web` apps (not an onboarded NSP resource type).

### Storage layout & dual credential pattern

Every competition has an immutable 8-char hex **id** (`uuid4().hex[:8]`) — the identifier in all API calls and table keys. Competition **names are not unique** (trial-and-error re-creation is allowed); the blob folder is `{sanitized-name}-{id}/`, stored on the entity as `FolderPath` (endpoints resolve id → FolderPath via `_competition_for`, which also checks access).

Blob container `fs-judgepapers`:
- `{name}-{id}/metadata.json` — id/name/createdBy/createdDate/judgingMethodOverrides/trainees (older ones also hold a `language`, no longer read); its existence defines the competition "folder". `save_competition_settings` stores only the `SETTINGS_KEYS` `judgingMethodOverrides` and `trainees` (any other key, a non-object body or `settings`, a malformed map or trainee list → 400; each value replaced wholesale) as a read-modify-write with optimistic concurrency: `_load_competition_metadata` returns `(dict | None, etag)` (None = missing or not a JSON object, which the save rebuilds from the row's `id`/`name`) and raises on a storage error (→ 503 `Storage unavailable, try again`, nothing written); `_write_competition_metadata` writes only if unchanged (`etag` + `MatchConditions.IfNotModified`, with `overwrite=True`, because with `overwrite=False` the SDK turns the 412 into `ResourceExistsError`) or create-only when the file was missing; on a conflict (`ResourceModifiedError` / `ResourceExistsError`) the save re-reads, re-merges and retries, `SETTINGS_SAVE_ATTEMPTS` (3) in all, then 409 `Settings changed meanwhile, try again`. So a save never wipes `createdBy` and never loses a concurrent save of the other key or a rename; two saves of the same key still end with the last one, since each sends its full value. `get_competition_details` and `generate_judging_papers` read the file with the same loader: a storage error is a 503 `Storage unavailable, try again` (generate: before anything is downloaded or generated), never a response or a run built from empty settings (which would let the UI save back an empty trainee list, or drop every trainee's packet); a missing file is empty settings, nothing written or logged. Details return `trainees` (sanitized; the UI sends the full list back on every save); generate takes them, like the overrides, from metadata.json only (a client-sent value is overwritten). `delete_file` refuses `metadata.json` and `init.md` (`RECORD_CONTROL_FILES`, 400 `Invalid filename`), which the pool refresh skips too.
- `{name}-{id}/{PREFIX}_{Suffix}.pdf` — uploaded FSM exports
- `{name}-{id}/judgePapers/...` — generated output (ZIPs + merged PDFs are recorded in `generatedpapers`; links are minted per response)

Tables: `competitions` is the **authoritative, permanent history** of every competition ever created (PartitionKey `GLOBAL`, RowKey = id; rows are never deleted — there is no blob-scan fallback anymore). Columns: `Name`, `FolderPath`, `Visible` (controls UI listing), `CreatedBy/CreatedDate` (`CreatedBy` blanked on delete), `DeletedDate/DeletedBy` (`user`/`auto-cleanup`, never an address), `DeletionDate` (a cached copy of the platform date, see Retention), `PlatformId` (see below; every record created since the platform clock has one), and usage counters for statistics (`UploadedFileCount`, `GenerateRunCount`, `LastGeneratedDate`, maintained best-effort by `_bump_competition_counters`). Deleting a competition removes its blobs and `generatedpapers` rows but only soft-deletes the `competitions` row (`Visible=false` + delete audit). Legacy name-keyed rows are lazily migrated by `list_competitions` (`migrate_legacy_row`: new id-keyed row with `FolderPath` = old name folder, generatedpapers re-keyed). `generatedpapers` records the generated files (PartitionKey = competition id; `BlobName`, `FileName`, `FileSize`, `Description` — no link: `get_competition_details` mints a fresh 15-minute read SAS per file after the access check, `_generated_file_links`, one user-delegation key per response; older rows' stored 5-day `Url` is never returned, only its blob name is used), `categories` is the category registry, `sentemails` is the send-e-mail audit log, download-link registry and rate-limit source (PartitionKey = competition id, RowKey = sha256 hex of the link token with `KeyKind` `sha256` — rows from before 2026-11 hold the clear token and no `KeyKind`; `Channel` `email`|`link`, `SentBy`, `SentByName`, `SentByTid`, `SentByOid`, `SentByAdmin`, `RevokedUtc`/`RevokedByTid`/`RevokedByOid` once revoked, `To`, `Cc`, `FileName`, `Language`, `SentDate`, `LinkExpiry`, `MailgunId`, `DryRun`, `DownloadCount`, `LastDownloaded`), deleted with the competition's blobs because it holds recipient addresses (a failure there aborts the delete before the soft-delete, so it can be retried); sends are also counted in `EmailSentCount` on the `competitions` row.

**Platform binding.** The site owns the competition registry and its nav selector's "active competition" (a GUID). `POST /resolve_competition` (`{platformId, name}` → `{id, name, created, deletionDate}`) maps that GUID onto this tool's own record so the site's UI needs no per-tool competition list: first checks read access to the platform competition (404 `platform_not_found` / 503 `platform_unavailable`, before the 410 check so nothing leaks), then looks it up by `PlatformId` (server-side filter, `Visible is False` filtered in Python because legacy rows lack the property and soft-deleted rows keep their `PlatformId` while their blobs are gone; newest `CreatedDate` wins; when the sanitized platform name differs from the stored `Name` and the caller has write or owner, `_sync_competition_name` MERGE-writes the new `Name` and best-effort rewrites `name` in `metadata.json` (a conditional write on the etag it read: a file that changed meanwhile, is missing or unreadable is left alone), so a rename on the site follows through — `FolderPath` is deliberately immutable, blob paths and generated-paper URLs hang off it) → else creates one via `create_competition_record` (requires a `platform_id`; `resolve_competition` is the only creator — the standalone `create_competition` route is gone). Unbound records are **never adopted by name** any more (removed with competition access: it let anyone capture another user's record); a legacy unbound record stays admin-only. A *new* binding (creation) needs the platform row to be readable: 404 `platform_not_found` when the registry has no such competition, 503 `platform_unavailable` when it can't be read; only a deployment without `PLATFORM_STORAGE_ACCOUNT` (local dev) binds without a date. `migrate_legacy_row` never writes a `PlatformId` (and only an admin's `list_competitions` runs it). The legacy `list_competitions` (read-only apart from the legacy re-keying) and `delete_competition` routes remain; `create_competition` and `extend_competition_deletion` are removed — extending happens only on the platform (`POST /api/competitions/{id}/extend`, called by the site).

**Retention (one platform clock).** One rule per competition, owned by the platform: the site's registry holds each competition's deletion date (created + 60 d, extended a week at a time on the site only) and mirrors the non-personal part into its own table `retentionclock` (PK `COMPETITION` / RK the lowercase GUID; `DeletionDate`, `Status`, `PurgedUtc`). This tool reads **only** that table (never the registry's `competitions`, which holds addresses and IPs), read-only through a Storage Table Data Reader grant scoped to it (site repo's `shared-data-access.bicep`; `PLATFORM_CLOCK_TABLE` overrides the name). It has **no clock of its own** and no extend route; the row's `DeletionDate` is only a cached copy of the platform date (written by `_sync_local_deletion_date` on resolve, details and the timer) for display and the send cap. `platform_clock.py` reads the platform — keep it **byte-identical** with fs-protocolgenerator and fs-scoremodifier: `normalize_platform_id` (lowercase GUID or None — used before every platform read and every local lookup/store, so a differently-cased GUID never binds a second record; `find_competition_by_platform_id` also finds and rewrites a row stored under another casing), `read_platform_clock` → `{deletionDate, status, purged}`, `None` when the row is missing or `PLATFORM_STORAGE_ACCOUNT` is unset, `PlatformClockUnavailable` on any other failure including a missing table (`TableNotFound`); `platform_says_delete(clock)` is true **only** for `Status == "deleted"` or `PurgedUtc` — a passed date alone never deletes (the platform may be in dry-run, or the competition was just extended). `_platform_clock_reader` builds ONE platform table client (per request, per sweep) and returns `(clock, state)` with state `ok` / `not_found` / `unavailable` / `off` / `unbound`. `resolve_competition` returns 400 for a platformId that isn't a GUID and 410 `platform_deleted` (creating nothing) for a deleted/purged platform competition; `resolve_competition` and `get_competition_details` return the platform's `deletionDate` (cached copy as fallback); the send flow caps the link at it. The 04:00 UTC timer (`run_auto_deletion`, an hour after the platform's 03:00 sweep so it follows the platform's verdicts the same night): bound row with the clock readable → deleted when `platform_says_delete`, otherwise only the cached date is synced; clock unreadable (incl. missing table) or `PLATFORM_STORAGE_ACCOUNT` unset → **skipped** with an error log. Legacy rows without `PlatformId` (from before the platform) are deleted on their stored `DeletionDate` (`LEGACY_DELETION_DATE`, long past, when they have none) and nothing new is written for them. **Orphans** (the platform can no longer decide about them): a live row with no `PlatformId` (legacy name-keyed rows included) or a non-GUID one, or whose clock row a *successful* read did not find, is deleted with the same `_delete_competition_data` flow once it is **more than 60 days old** (`CreatedDate`; without one, the newest of `LastGeneratedDate`/`LastStatisticsDate`/the Table `Timestamp` — `platform_clock.record_age_reference`); younger orphans are kept with a warning, and a read error is never "not found" (skipped). Safety rails: one probe of the clock table per run (`platform_clock.orphan_sweep_allowed`) — unreadable, unconfigured, or **zero rows while the tool has bound rows** (wrong table/account) → the orphan step is aborted for that run with an error log; `ORPHAN_PURGE_ENABLED` (Bicep param `orphanPurgeEnabled`, default on, GitHub var `ORPHAN_PURGE_ENABLED=false` = kill switch) off → it only logs "would delete"; the timer logs the per-run counts (`orphaned`, `orphan_kept`, `orphan_dry_run`, `orphan_skipped`). **No addresses outlive the data:** `_delete_competition_data` blanks `CreatedBy` and stores `DeletedBy` = `user` | `auto-cleanup` (metadata.json with `createdBy`, the `sentemails` rows and `importedBy` blob metadata go with the data), and every nightly run also calls `_scrub_hidden_rows`, which blanks any `CreatedBy`/`DeletedBy` still holding something other than `""`, `-`, `user`, `auto-cleanup` on hidden rows deleted before this. Logs carry no addresses or personal names either (auth logs say only which header identified the caller; the send log counts recipients), and `function_app.py` raises the Azure SDK's `azure.core.pipeline.policies.http_logging_policy` logger to WARNING at import, because its INFO lines carry every storage URL (blob paths, table keys); `host.json` log levels don't reach Python logger names (`tests/test_logging.py`). Logs are kept **90 days**: `function.bicep` links the App Insights component to its own Log Analytics workspace `log-fs-judgepapers-<env>` (`retentionInDays: 90`) and sets `RetentionInDays: 90` on the component (`logRetentionDays`).

**Pool refresh.** Blobs copied in from the pool carry `poolSource` / `poolUploadedUtc` / `importedBy` blob metadata (`_copy_pool_blob`, shared by `import_platform_file` and the refresh). Both read paths — `get_competition_details` and `generate_judging_papers` — first run `_refresh_from_pool`, which re-copies any file the tool *already holds* whose pool copy (`uploads/` or `fsm/`, newest of the two) is newer than the stamped `poolUploadedUtc`, so an FSM re-export under the same stable filename replaces the tool's copy automatically instead of generating from a stale one. It never adds or deletes files — new pool files still need an explicit import — and it is best-effort: every failure is logged and swallowed. `get_competition_details` reports what it replaced as `refreshedFromPool` and returns per-file `uploadedUtc` (the pool upload / FSM push time — what the UI shows), `lastModified` (when this copy was written) and `poolSource`.

Every storage client helper supports two credential modes and new storage code must too: managed identity when `AzureWebJobsStorage__accountName` is set (production; SAS via user-delegation key), connection string via `AzureWebJobsStorage` otherwise (local dev; SAS via account key).

### Category/filename parsing

FSM filenames are `{CATEGORY_ABBREVIATION}{SEGMENT_MARKER}_{Suffix}.pdf` (e.g. segment markers `QUAL`/`FNL`, split suffixes `#N`). Abbreviations are not hardcoded — they live in the `categories` Azure Table (RowKey = abbreviation, with `DisplayName`, `DisplayNameFi`, `JudgingMethod` = ISU|MUPI) and are matched longest-prefix-first. `categories.py` caches the table in memory for 5 minutes. The table's `JudgingMethod` is only the *default*: synchronized-skating categories (`is_synchronized_skating`, a casefold compare of the PartitionKey, since live rows use both `Synchronized skating` and `Synchronized Skating`; `get_competition_details` counts the competition's types casefolded the same way and shows one sentence-cased spelling, so such a competition is "Synchronized skating", not "Mixed") can be overridden per competition via `metadata.json`'s `judgingMethodOverrides` (`{abbreviation: ISU|MUPI}`, validated on write by `save_competition_settings`, sanitized on read). `get_competition_details` applies them — each file gets the effective `judgingMethod` plus `defaultJudgingMethod` and `judgingMethodOverridable` — and `_compute_statistics` applies them via `options['judgingMethodOverrides']`, which `generate_judging_papers` reads from metadata.json (a client-sent value is ignored); the PDF pipeline itself never reads the judging method. This parsing logic is duplicated in spirit on the frontend (`validate.ts` consumes the parsed structure from `get_competition_details`).

Human-readable category and segment names aren't in filenames; both come from line 2 of each (always uploaded) `JudgesSheetAll.pdf`, **as FSM printed them, in the competition's own language** — `categories.names_from_sheet_line` (shared by `function_app.py`'s `get_competition_details` and `processor.py`). The table's `DisplayName`/`DisplayNameFi` only locate where the category ends on that line (case-, space- and punctuation-insensitive, on a word boundary; a printed `#N` is kept, a split group's `#N` added when missing); a line no table name matches is split before a known segment name or at a 2+ space gap (`combined_schedule.split_title`); and when the table name is only the *start* of the printed one ("AIKUISET MUPI FREE SKATING" for the row "Aikuiset"), the split before the known segment name wins (`combined_schedule.is_known_segment`), so the segment is never "MUPI FREE SKATING". The table's Finnish name stands in only when no line could be read. There is **no language option** any more (the site's "Use English category names" toggle and `options.language` are gone; the table's English names are never shown): the segment cover's category, the title fallback, the statistics' `categories`, and `get_competition_details`' structure keys and each file's `category` (no `categoryFi`; no `language` in the response) all use the printed name.

## Branch / Deploy Strategy

**Flow (no long-lived `test` branch):** branch from `main` → dispatch `deploy.yml` on that branch with `environment=test` → PR to `main` → merge with **squash** (one commit per release on `main`) → push to `main` deploys prod → the branch is auto-deleted on merge. `main` is guarded by the "Protect main" ruleset: PR required, code-owner review (`.github/CODEOWNERS`: `* @mmaraa`), squash only, the `build` and `pytest` checks (`.github/workflows/ci.yml`, every PR — `build` installs `requirements.txt`, imports the dependencies and byte-compiles the backend; `pytest` runs `infra/functions/tests`) must pass, no force-push/deletion; repository admins can bypass, which is how the owner merges their own PRs. The `prod` GitHub environment only accepts deployments from `main`; `test` accepts any branch and holds whichever was deployed last. Dependabot opens its PRs against `main` like any feature branch. `.github/workflows/deploy.yml` has two deploy jobs — infra (Bicep) then backend (Functions ZIP) — targeting the matching GitHub environment: **push to `main` auto-deploys prod**; **`test` is manual-only** via `workflow_dispatch` (run the workflow from the branch whose code you want, pick the environment) — there is no `test`-branch push trigger. This mirrors the figureskatingtools-site repo. There is **no frontend job and no Entra/Graph step** any more; the environments need only `AZURE_CLIENT_ID` + `PROXY_SHARED_SECRET` + `MAILGUN_API_KEY` (Mailgun domain sending key for `figureskatingtools.com`, EU region; empty = e-mail dry run) secrets, the optional `EXAMPLE_VIDEO_URL` var, the optional `ORPHAN_PURGE_ENABLED` var (`false` = the nightly orphan step only logs; unset = on), the `PLATFORM_STORAGE_ACCOUNT` var (the site's `stfsplat*` account: pool import and the retention clock — required in every deployed environment; empty = pool import off and auto-deletion of bound competitions skipped), and the `AZURE_TENANT_ID` / `AZURE_SUBSCRIPTION_ID` / `LOCATION` / `RESOURCE_GROUP_NAME` vars (`AUTH_CLIENT_ID`, `AUTH_APP_OBJECT_ID` and `CUSTOM_DOMAIN` are obsolete and can be deleted). All jobs in `deploy.yml` pin `runs-on: ubuntu-26.04` rather than `ubuntu-latest` ([actions/runner-images#14748](https://github.com/actions/runner-images/issues/14748) flips `-latest` from 24.04 to 26.04 between 2026-10-19 and 2026-11-19); bump that label deliberately — verify via a `test`-environment dispatch first, roll back to `ubuntu-24.04` if needed — and never set it back to `ubuntu-latest`.
